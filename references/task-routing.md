# Task Routing

这是轻量级任务选择规则，不是 Agent Router。先看输入材料，再看教师目的；若两者冲突，以材料门禁为准。任务确定后，按 `curriculum-alignment.md` 选择对应课程标准维度，再进入工作流；课程标准对齐不改变材料门禁。

| 输入材料 | 教师目的 | 任务 |
|---|---|---|
| 没有具体错误证据，只描述“不会 / 学不好 / 总做错 / 总搞错 / 掌握不好 / 经常出错”等学习表现 | 判断需要先查什么 | `diagnosis_report` |
| 学生原话、作答、解题步骤、错误选项、作图、实验记录或明确错误推理过程 | 分析这一次具体错误；若用户另要求分析稳定认知模型，再追加误概念分析 | `error_analysis_report`（必要时后续 `misconception_report`） |
| 用户直接询问某概念的典型/群体性错误认识及纠正方法 | 分析一般性错误概念 | `misconception_report` |
| 教案原文（至少有教学目标与流程） | 找问题、评估设计 | `lesson_design_review` |
| 教案原文 + 明确要求修改 | 修改原教案 | `lesson_plan_revision`（先做必要的 `lesson_design_review`） |
| 已完成实验、数据/现象/结果 | 判断数据是否支持结论、误差是否足以解释结果 | `experiment_plan` 的“实验结果分析”分支，不新增 workflow |
| 教师提出导入、活动、难点或取舍困惑 | 给方向与决策支持 | `design_coaching` |

## 选择规则

1. 先检查是否存在具体错误证据：学生原话、作答、解题步骤、错误选项、作图、实验记录或明确错误推理过程。
2. 有完整题干 + 学生实际作答时，优先 `error_analysis_report`；不要把一次具体错误改写成泛泛的 `misconception_report`。
3. 有具体错误证据但没有完整题干时，仍先做基于所给证据的具体错误分析；若用户明确要求分析其稳定认知模型，可追加 `misconception_report`，但必须说明证据范围和不能确定之处。
4. 没有具体错误证据，只说“不会 / 学不好 / 总做错 / 总搞错 / 掌握不好 / 经常出错”时，优先 `diagnosis_report`；频率词本身绝不能触发 `misconception_report`，只能确认学习困难或表现异常。
5. 用户直接询问某概念的典型错误认识、群体性误区或纠正方法时，使用 `misconception_report`；此时分析的是一般模型，不是对某个学生的确定性诊断。
6. 输入同时含学习困难和具体错误证据时，具体证据优先：先做 `error_analysis_report`；只有用户明确要求或后续任务需要稳定认知模型时，才追加误概念分析。
7. 只有教案且教师问“有什么问题”，用 `lesson_design_review`；教师明确说“请改写/压缩/降低难度”，用 `lesson_plan_revision`。
8. 教案评审必须标出【已检查】与【未检查】；缺少器材、数据、评价、板书或时间时，不得声称完成对应的完整评审。
9. “指出问题/给改进建议/修改几处”输出局部建议；“重做一份完整教案/完整改写”输出完整教案。
10. 教师只要思路、方向或取舍时，用 `design_coaching`，不给完整教案。
11. 材料不足时，先指出缺口及其影响，再给仍然可做的部分；不能用通用模板冒充完成了具体任务。

## 相邻任务的输出边界

- `diagnosis_report`：在没有具体错误证据时，判断需要进一步区分的理解状态，并给出可验证的诊断任务；不得直接认定某个错误概念。
- `misconception_report`：分析用户明确询问的典型/群体性错误模型，或基于具体证据讨论可能的稳定认知模型；必须说明证据范围，不能声称该生一定持有该模型。
- `error_analysis_report`：逐步对应题干与作答，定位这一次具体错误，并给出验证是否改正的办法。
- `lesson_design_review`：指出原教案的问题、证据和优先级，不直接重写全文。
- `lesson_plan_revision`：根据请求体量，在保留可取设计的前提下给出局部修改或完整修订稿，并列明改动与仍存问题。
- `experiment_plan` 的“实验结果分析”分支：只根据已提供数据、现象和误差证据判断支持程度，不把数据分析冒充新的实验设计。
- `design_coaching`：给多个方向、依赖条件和取舍，让教师继续做设计决策。
