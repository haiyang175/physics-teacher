# Curriculum Alignment

课程标准对齐层连接：`Teacher Request → Task Routing → 学段/主题/版本识别 → Curriculum Alignment → Physics Knowledge → Workflow → Teacher Output → Alignment Check`。

## 使用步骤

1. 确认学段、年级、主题、任务类型和用户指定的课程标准版本。
2. 选择 `curriculum-junior-high.md` 或 `curriculum-senior-high.md`，并按 `curriculum-framework.md` 判断引用等级。
3. 为当前任务选 `primary focus`、`secondary focus`、`non-focus`；不机械覆盖四项核心素养。
4. 把相关要求转为“学生表现 → 学习任务 → 学习证据 → 评价方式/标准”。
5. 完成后检查对齐是否真正改变了目标、活动、问题、评价或反馈；若没有，不要为了形式添加课程标准段落。

## 16 个工作流映射

| Task | 课程标准维度 | 必须影响的输出字段 |
|---|---|---|
| `lesson_plan` | 课程目标、内容要求、学业要求、教学建议、评价建议 | 实施条件、教学目标、学习活动、学习任务、评价任务、课程标准对齐表。 |
| `concept_explanation` | 内容要求、学业要求 | 解释深度、表征、适用条件、学生应达到的理解表现。 |
| `diagnosis_report` | 学业要求、核心素养 | 学习表现、诊断任务、能力差异、后续证据。 |
| `misconception_report` | 内容要求、学业要求、核心素养 | 概念理解、推理表现、诊断证据、纠正与验证。 |
| `experiment_plan` | 科学探究、内容要求、学业要求、教学建议 | 问题、猜想、方案、变量、证据、数据、结论、交流、反思。 |
| `physics_model` | 内容要求、学业要求 | 模型建立、对象、条件、变量、推理和适用范围。 |
| `problem_review_report` | 内容要求、学业要求、评价建议 | 知识、能力、情境、认知水平、评价价值。 |
| `problem_revision_report` | 内容要求、学业要求 | 修改后的任务、支架、难度与评价目标。 |
| `assessment_plan` | 学业要求、核心素养、评价建议 | 评价任务、学生表现、证据、评分标准、反馈。 |
| `homework_plan` | 内容要求、学业要求、评价建议 | 分层任务、能力目标、支架、完成标准、反馈。 |
| `error_analysis_report` | 学业要求、学生表现 | 错误类型、能力缺口、验证证据。 |
| `lesson_design_review` | 课程目标、内容要求、学业要求、教学建议、评价建议 | 对齐审查、活动与评价一致性、证据边界。 |
| `lesson_plan_revision` | 原设计、标准要求、审查结论 | 实施条件、局部修改或完整教学设计的对齐修订。 |
| `design_coaching` | 教学建议、核心素养、评价建议 | 设计方向、取舍、学生任务、证据和评价思路。 |
| `content_deepening` | 内容要求、学业要求 | 内容深度、学段边界、数学前置、课堂可用性。 |
| `pedagogy_theory` | 课程理念、教学建议、评价建议 | 理论与活动、证据、评价之间的对应关系。 |

## 对齐闸门

- 用户明确指定版本：优先使用，不能无说明混用版本。
- 用户未指定版本但学段明确：使用对应学段 references。
- 学段不明确且初高中皆可能：先要求明确学段。
- 无法确认具体条文：按 Level 3 输出一般建议，不作“课程标准明确要求”的断言。

## 评价闭环

所有涉及评价的任务至少建立以下链条：

```text
课程标准要求
    ↓
学生表现
    ↓
学习任务
    ↓
学习证据
    ↓
评价方式
    ↓
评分标准与反馈
```

## 复合任务闭环

在既有“前序结论 → 后续字段”表中额外记录：

```text
课程标准要求
    ↓
教学目标
    ↓
学习活动
    ↓
学习证据
    ↓
评价任务
```

课程标准结论若未进入后续字段，必须说明原因；不能只在开头增加一段标准分析。
